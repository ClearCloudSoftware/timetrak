# TimeTrak v0.2 — Tray Popover Redesign + Polish

**Date:** 2026-05-22
**Status:** Approved for planning
**Builds on:** v0.1 (`docs/superpowers/specs/2026-05-22-timetrak-design.md`)

## Summary

v0.2 rebuilds the tray popover into a "home base" that shows today's
timers, lets you switch contexts in one or two clicks, and surfaces
Dashboard / Export / Settings as inline icons. It also fixes two
chrome bugs from v0.1: the popover appears centred on screen instead
of anchored to the tray icon, and the Dock icon shows during
`tauri dev`. The data model and frozen Rust signatures are unchanged.

## Goals

- Anchor the popover to the tray icon position.
- Hide the macOS Dock icon during dev (production already hidden).
- Show today's entries in the popover, with descriptions inline.
- Click an entry to resume it (open a prefilled inline form, then Start
  performs the atomic stop + start).
- Surface Dashboard / Export / Settings as icons in the popover header,
  while keeping the existing right-click context menu.
- Standardise the timer description: rename "Note" → "Description",
  cap at 250 characters with a live counter.
- Show today's total time at the bottom of the popover.

## Non-goals (v0.2)

- Schema migrations. The existing `time_entry.note` column carries
  the description.
- New Tauri commands beyond a single `open_window(name)` helper.
- Dashboard or Settings window redesigns (Dashboard's table picks up
  the renamed "Description" cell label but is otherwise untouched).
- New entries / new categories beyond what already exists.
- Weekly / monthly summaries in the popover (Dashboard already
  handles ranges other than today).
- Localisation, themes, dark mode.

## Architecture

No layering changes. The Rust core (`repo`, `timer`, `commands`)
stays as in v0.1. The popover (`src/windows/tray/`) is rebuilt around
a richer component tree. One new Tauri command (`open_window`) is
added.

### 2. Hide Dock icon in dev (TODO 7)

Add to `src-tauri/src/main.rs` setup, immediately before the existing
DB open call:

```rust
#[cfg(target_os = "macos")]
app.set_activation_policy(tauri::ActivationPolicy::Accessory);
```

This sets the activation policy at runtime. In dev mode (where
`LSUIElement` from `Info.plist` doesn't apply, because the binary is
not bundled), this hides the Dock icon. Production builds keep working
via the existing `LSUIElement = true` in `Info.plist`.

### 3. Anchor popover to the tray icon (TODO 4)

`TrayIconEvent::Click` carries the icon's screen position via the
`rect` field (`tauri::Rect`). In the click handler:

```rust
.on_tray_icon_event(|tray, event| {
    if let TrayIconEvent::Click {
        button: MouseButton::Left,
        button_state: MouseButtonState::Up,
        rect, ..
    } = event {
        toggle_tray_window(tray.app_handle(), Some(rect));
    }
})
```

`toggle_tray_window` accepts an `Option<tauri::Rect>` and, when
positioning the popover for the first time (or repositioning after
the tray icon moves), sets:

- macOS: `x = rect.position.x + rect.size.width / 2 - POPOVER_W / 2`,
  `y = rect.position.y + rect.size.height + 4`.
- Windows (taskbar typically at bottom): `x = same`,
  `y = rect.position.y - POPOVER_H - 4` (clamped to monitor bounds).

`POPOVER_W = 340`, `POPOVER_H = 440` (constants).

The position is set via `WebviewWindow::set_position(
PhysicalPosition::new(x, y))` after the window is created and made
visible. We call it on every show, not just on first create, so the
popover follows the tray icon if the user changes monitor
configuration.

If `rect` is unavailable (e.g., menu-triggered "Show Dashboard"
opening doesn't go through `toggle_tray_window`), fall back to
Tauri's default position. The popover is not opened from any path
that lacks the rect today.

#### Export action

The popover's Export icon does the same work as the Dashboard's
"Export CSV" button, but defaults to today's local-day range:

```ts
const { startUtc, endUtc } = todayRangeUtc();
const csv = await api.exportCsv(startUtc, endUtc);
const path = await save({ defaultPath: 'timetrak-today.csv', filters: [...] });
if (path) await writeTextFile(path, csv);
```

The `todayRangeUtc()` helper lives in `src/windows/tray/format.ts`
and computes `[local-midnight-of-today → local-midnight-of-tomorrow]`
in UTC ISO-8601, mirroring the `startOfWeekUtc` pattern in the
dashboard.

### 5. `open_window` Tauri command (supports TODO 3)

`src-tauri/src/commands/windows.rs`:

```rust
use tauri::{AppHandle, Manager, WebviewUrl, WebviewWindowBuilder};
use crate::error::{AppError, AppResult};

#[tauri::command]
pub fn open_window(app: AppHandle, name: String) -> AppResult<()> {
    if name != "dashboard" && name != "settings" {
        return Err(AppError::Invalid(format!("unknown window: {name}")));
    }
    if let Some(w) = app.get_webview_window(&name) {
        w.show().map_err(|e| AppError::Other(e.to_string()))?;
        w.set_focus().map_err(|e| AppError::Other(e.to_string()))?;
        return Ok(());
    }
    let title = match name.as_str() {
        "dashboard" => "TimeTrak — Dashboard",
        "settings" => "TimeTrak — Settings",
        _ => "TimeTrak",
    };
    WebviewWindowBuilder::new(
        &app,
        &name,
        WebviewUrl::App(format!("index.html?window={name}").into()),
    )
    .title(title)
    .inner_size(900.0, 600.0)
    .build()
    .map_err(|e| AppError::Other(e.to_string()))?;
    Ok(())
}
```

Registered via `timetrak_handlers!` (append-only edit to
`commands/mod.rs`). The existing private `open_window` helper in
`main.rs` is **deleted**; the menu handler in `main.rs` calls
`commands::windows::open_window(app.clone(), "dashboard".into())`
directly (or inlines the body — either is fine; pick whichever keeps
`main.rs` smallest).

TypeScript wrapper in `src/lib/api.ts`:

```ts
export const openWindow = (name: 'dashboard' | 'settings') =>
  invoke<void>('open_window', { name });
```

INDEX gains a row:

| `openWindow(name)` | `open_window(name: String) -> AppResult<()>` | v0.2 |

#### Popover state machine

`TrayPopover.tsx` holds three mutually exclusive modes:

```ts
type Mode =
  | { kind: 'browse' }
  | { kind: 'new' }
  | { kind: 'edit'; sourceEntry: TimeEntry };
```

- `browse` is the default. Header, running banner (if any),
  "＋ New timer" affordance, today's list, footer.
- `new` swaps the "＋ New timer" line for an expanded
  `InlineTimerForm` with blank fields. Cancel returns to `browse`.
- `edit` swaps the *clicked* entry's row for an `InlineTimerForm`
  prefilled with that entry's category, project, and description.
  Cancel returns to `browse`. Start invokes `switchTimer(...)`
  (which already handles the atomic stop + start; the just-stopped
  current entry appears at the top of the list on the next render).

The running entry is **not** clickable for resume — only stopped
entries are. The running banner has the only Stop affordance.

#### `RunningBanner.tsx`

Extracted from the current `RunningView` in `TrayPopover.tsx`. Same
behavior:

- `entry: TimeEntry` prop
- Subscribes to its own `setInterval(1s)` for the elapsed counter
- "Stop" button (text-only red border, as today) calls
  `api.stopTimer()` and invalidates `qk.timerState`
- Two-line layout: line 1 = category · project, line 2 = description,
  then a large monospace HH:MM:SS counter and Stop on the right

Existing `formatElapsed`, `elapsedSeconds` helpers move with it.

#### `TodayList.tsx`

Props:

```tsx
interface Props {
  entries: TimeEntry[];      // already fetched, today only
  categories: Category[];
  projects: Project[];
  runningId: Id | null;      // exclude this from the list
  onResume: (entry: TimeEntry) => void;  // → switches popover to 'edit' mode
}
```

Behavior:

- Filters `entries` to exclude the running one.
- Sorts descending by `started_at`.
- Renders `<TodayEntryRow>` per entry.
- Empty state: muted line "No timers stopped today yet."

#### `TodayEntryRow.tsx`

Two-line row, click → `onResume(entry)`:

- Line 1: `HH:mm` (local) · colored dot + category name · ` · ` + project name (when set) · right-aligned duration `Xh YYm`
- Line 2: muted description (`text-xs text-gray-500`), omitted when null
- Row has `cursor-pointer hover:bg-gray-50 transition-colors rounded`
  padding `px-2 py-1.5`
- Focusable via `tabIndex={0}` + keyboard Enter triggers `onResume`

#### `InlineTimerForm.tsx`

Reusable mini-form for both `new` and `edit` modes.

```tsx
interface Props {
  initial: { categoryId: Id | null; projectId: Id | null; description: string };
  categories: Category[];
  projects: Project[];
  onCancel: () => void;
  onSubmit: (v: { categoryId: Id; projectId: Id | null; description: string | null }) => void;
}
```

- Form fields exactly mirror `CategoryPicker` (in fact, internally
  it reuses `CategoryPicker` for the three controls).
- `Start` button (primary blue) is disabled unless `categoryId` is
  non-null.
- `Cancel` button (text-only gray) → `onCancel()`.
- On `Start`, `onSubmit({ categoryId, projectId, description })` is
  called. The parent decides whether to invoke `switchTimer` (when
  something is running) or `startTimer` (when nothing is). Both
  commands accept the same args; the parent uses `switchTimer` if
  `timer.data.running` is non-null, else `startTimer`.

#### `TodayFooter.tsx`

Bottom strip:

- Computes total seconds across today's entries (running entry
  contributes `now - started_at`, others contribute `ended - started`).
- Renders one line: `Today: 4h 23m` (`text-sm font-medium`,
  `px-3 py-2 border-t border-gray-200`).
- Updates live for the running entry via the same 1-second tick used
  by `RunningBanner` (lifted into `TrayPopover`).

#### `HeaderIcons.tsx`

Right-aligned icon row inside the popover header. See section 4.

### 7. Wiring

- `TrayPopover.tsx` queries `qk.categories`, `qk.projects`,
  `qk.timerState`, **and** `qk.entries(todayRangeUtc())`.
- Subscribes to both `onTimerChanged` and `onEntriesChanged`,
  invalidating `qk.timerState` and the today range respectively.
- Computes `today = todayRangeUtc()` once per mount (memoised).
- Holds `mode: Mode` state, mutates on user actions described above.

## Key user flows

### Context switch (most-frequent flow)

1. Coding is running. User is invited to a meeting.
2. User clicks tray icon → popover appears under the tray icon.
3. User clicks the "Meeting" row from earlier today.
4. The Meeting row expands into the `InlineTimerForm` with
   category=Meeting, project=(its previous project), and the
   description from that previous entry.
5. User adjusts description if needed (e.g., "1:1 with Alice"), clicks
   `Start`.
6. `switchTimer(...)` is invoked. The atomic transaction stops Coding
   and starts a new Meeting entry.
7. The popover re-renders: running banner shows Meeting, the
   newly-stopped Coding appears at the top of the today's list with
   its accumulated duration. The InlineTimerForm collapses, popover
   is back in `browse` mode.

### Start fresh

1. User has no running timer.
2. User clicks tray icon → popover appears.
3. User clicks "＋ New timer".
4. `InlineTimerForm` expands blank.
5. User picks category, optionally project, optionally description,
   clicks `Start`.
6. `startTimer(...)` is invoked. Running banner appears.

### Stop

1. Running timer is shown in the banner at top.
2. User clicks `Stop` in the banner.
3. `stopTimer()` is invoked. Banner disappears. The just-stopped
   entry appears at the top of the today's list.

### Quick export

1. User clicks the `⤓` icon in the header.
2. `exportCsv(todayStart, todayEnd)` returns CSV string.
3. Native save dialog opens with default name `timetrak-today.csv`.
4. User picks a location; CSV is written.

## Error handling

- `switchTimer` / `startTimer` errors are surfaced inline in the
  `InlineTimerForm` (red text below Cancel/Start), same pattern as
  today's `TrayPopover`.
- `stopTimer` errors are surfaced as a toast — non-blocking — at the
  bottom of the popover. The banner stays open until the user clicks
  Stop again or it succeeds on retry.
- `openWindow` errors (Rust → "unknown window: …") are unreachable in
  practice (the frontend only ever passes valid names), but we still
  catch and `console.warn` on the JS side rather than crash.
- Export errors: catch + alert (same as today's Dashboard Export).
